# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`bizdays` is an R package (on CRAN) for business-day calculations from a list of holidays plus nonworking weekdays. Used in fixed income and derivatives pricing.

## Commands

Run from the repo root in R (or `Rscript -e '...'`):

```r
devtools::document()                 # regenerate man/*.Rd and NAMESPACE from roxygen comments
devtools::test()                     # run all tests (testthat)
devtools::test(filter = "getdate")   # run one file: tests/testthat/test-getdate.R
devtools::check()                    # full R CMD check (what CI runs)
pkgdown::build_site()                # docs site in docs/
```

`man/` and `NAMESPACE` are generated by roxygen2 — edit the `#'` comments in `R/`, never the `.Rd` files directly.

## Architecture

- **Calendar object** (`R/calendar.R`, `Calendar_`): a calendar is a closure-based S3 `list` of class `"Calendar"`. At creation it precomputes, for every day from `start.date` to `end.date`, an `is.bizday` vector, a forward index (`cumsum`) and a reverse index (`rev_index`). `bizdays`, `add` (offset), `seq` and `adjust.*` are lookups into these vectors via `match()` on integer dates. Dates outside the calendar range give `NA` or an error ("Given date out of range."). The default range is `min(holidays)`..`max(holidays)`, or 1970-01-01..2071-01-01 with no holidays.
- **Weekday codes**: weekdays are stored as `as.integer(date) %% 7`, so 1970-01-01 (a Thursday) is 0. See `weekdays_codes` in `Calendar_`.
- **Calendar register**: `create.calendar()` stores every calendar in the environment `.CALENDAR_REGISTER` (exposed by `calendars()`). All public functions take `cal` as a name or a `Calendar` object and resolve it with `check_calendar()`. The default calendar comes from `bizdays.options$get("default.calendar")` (`R/bizdays.options.R`).
- **Public API is S3 generics** dispatching on the date argument (`bizdays.default` → `as.Date` → `bizdays.Date`, the same for `offset`, `bizseq`, `is.bizday`, `adjust.*`). They handle vector recycling and the `adjust.from`/`adjust.to` rules, then call the calendar's closures.
- **`financial` flag**: financial calendars do not count the end date; non-financial ones return one more day.
- **Built-in calendars**: JSON files in `inst/extdata/` (`actual`, `weekends`, `Brazil/ANBIMA`, `Brazil/B3`, `Brazil/BMF`). They are loaded by `load_builtin_calendars()` in `.onAttach` (`R/zzz.R`) through `load_calendar()` (`R/calendar-export.R`). The file name is the calendar name with `/` replaced by `_`. Since this runs on attach, code using `bizdays::` without `library(bizdays)` must call `load_builtin_calendars()` first.
- **`getdate`** (`R/getdate.R`): parses expressions like `"10th wed"`, `"last bizday"`, `"next mon"` against a reference (year, `"YYYY-MM"`, or dates) built by `ref()`, which returns S3 classes `by_year` / `by_month` / `by_day`.

## Conventions

- `DESCRIPTION` has an explicit `Collate:` field — a new `R/` file must be added there, or it will not be loaded.
- Updating holidays of a built-in calendar = editing its JSON in `inst/extdata/` (`data-raw/prepare_json.R` shows how they were generated from calendar objects) and adding a line to `NEWS.md` under the current version.
- Tests use the old testthat style (`context()`), and many depend on the built-in calendars (e.g. `"Brazil/ANBIMA"`) and on the default calendar being `"actual"`.
